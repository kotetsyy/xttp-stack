## [0.19.3] - 2026-11-05

### Restored
- Исходный интерфейс 0.18.3 восстановлен непосредственно из Git-коммита `a2c0fe7`, а не перерисован по его мотивам: оригинальные разметка, палитра, шрифты, фон, адаптивные стили и экран входа.
- Возвращены одностраничные вкладки с движущимся индикатором, исходные карточки с независимым раскрытием групп, встроенные таблицы правил, прежний live-график и модальные окна.
- Сохранены оригинальные keyframes, переходы, анимации строк и индикаторов; необходимые изменения ограничены подключением к защищённым API и worker обновлений.

### Bug Fixes
- Прежние формы используют актуальные CSRF-защищённые API. Сохранение группы остаётся одной атомарной транзакцией; невалидные значения и ошибки записи не уничтожают правки и не показываются как успех.
- Inline-добавление получает ID из той же транзакции: последующее редактирование не зависит от конкурентного добавления другой строки. Импорт отправляет текущий текст, не старое превью.
- На первой загрузке runtime-поля недоступны до получения настроек ядра: изменение одного параметра не перезаписывает остальные HTML-значениями по умолчанию.
- Принятое задание обновления сохраняется независимо от открытого окна. Повторное открытие восстанавливает наблюдение за тем же ID; успех отображается только по конечному результату worker.
- Сохранены серверные сессии, подтверждения перед отзывом сессии с черновиками, приватные backups, независимые обновления и проверяемое восстановление. Версии и настройки ядер не меняются.

## [0.19.2] - 2026-11-05

### Changes
- Возвращены прежняя графитовая палитра, центральная компоновка, верхние вкладки, карточки групп и модальное окно настроек вместо сайдбара.
- Редактор раскрывается внутри группы. Настройки не уничтожают черновик правил под окном; несохранённые runtime/VLESS-значения защищены подтверждением, скрытый мониторинг приостановлен.
- Сохранены транзакции правил, CSRF, приватные backups, независимый worker обновлений и проверяемый откат из 0.19.1.

### Bug Fixes
- Перезагрузка новой серверной версии учитывает черновик настроек; выход и смена собственного пароля предупреждают о черновике основной панели до отзыва сессии.
- Закрытый раздел обновлений не возвращает параметр `operation` после отмены начального запроса.
- При ошибках API длинные статусы не расширяют страницу на узком телефоне: верхние элементы прокручиваются внутри своей строки.

## [0.19.1] - 2026-11-05

### Bug Fixes
- Ручной updater запоминает версию прежней службы до изменения checkout/units. При сбое перехода из соседнего checkout восстановленная старая панель проверяется как старая версия, а не как версия нового установочного пакета.
- Если прежнюю версию определить нельзя, скрипт не объявляет восстановление проверенным. Исходная ошибка установки сохраняет ненулевой exit status даже после успешного отката.

## [0.19.0] - 2026-11-05

### Features
- Полная навигация «Правила / Мониторинг / Система»: отдельные адресуемые страницы вместо большого окна настроек, desktop master/detail и мобильный редактор с подписанной нижней навигацией.
- Правила загружаются страницами; dirty-строки, удаления и параметры группы сохраняются одной транзакцией с backup. Сохранение и подтверждённое применение разделены.
- Импорт повторно разбирает текущий текст на сервере; доступны превью, дубли, управляемые межгрупповые конфликты, обзор и объяснение маршрута.
- Трафик передаёт историю по cursor/epoch и имеет представления «График / Данные»; соединения сохраняют фокус, логи поддерживают tail/live, поиск, follow и смену эпохи.
- Обновления имеют сохраняемый ID, этап, конечный результат и отдельный статус восстановления. Независимый systemd worker переживает перезапуск панели.
- Панель запускается из постоянного checkout вместе с templates/static; установщик и обновлятор поддерживают переход с точной версии 0.18.5 без потери сессии или локальных правил.

### Security
- Все API-изменения требуют session-bound CSRF; browser Origin проверяется. HTTP-тело ограничено 2 MiB и абсолютным deadline 10 секунд.
- Xray проверяет кандидата native-валидатором до публикации; configs/backups — 0600, каталог secret-backups — 0700. Существующие managed-файлы ужесточаются без изменения содержимого.
- Installer, UI, CLI и timer используют общий проверяемый OS-lock; переданный descriptor проверяется, а не заменяется доверенным флагом окружения.
- Git-кандидат валидируется по неизменяемому commit SHA. Обновления не сбрасывают историю; восстановление полного старого checkout не затирает конкурентные пользовательские правки.

### Bug Fixes
- Невалидное применение mihomo больше не удаляет действующие provider-файлы: используются отдельные поколения и проверяемое восстановление.
- Ошибки рестарта, timeout или копирования проходят recovery; успешный rollback объявляется только после проверки байтов и готовности, с ограниченным ожиданием медленного старта.
- Timer определяет реальный bind панели по её service MainPID, а не по окружению собственного worker. Сбой компонента не теряется при обновлении других частей флота.
- Сбой сохранения оставляет черновик и отмечает строки; изменённый текст не подменяется старым import-preview, а поиск не скрывает реальные межгрупповые конфликты.
- Frontend фиксируется в памяти процесса до запуска HTTP; смена серверной версии предлагает безопасную перезагрузку и не превращает выполненную запись в ошибку.
- Короткий экран входа прокручивается, системные страницы доступны на 320px, интерактивные элементы и ссылки обзора имеют достаточные hit areas; добавлены labels, видимый focus и native-подтверждения.
- Подготовка первоначального конфига возобновляется по durable-журналу даже после публикации; произвольная правка не принимается за штатный результат.

## [0.18.5] - 2026-11-04

### Security
- Панель по умолчанию слушает `127.0.0.1`; доступ через SSH-туннель или HTTPS reverse proxy.
- Уникальный начальный пароль хранится в локальном `bootstrap.password` с правами 0600; старый `admin/changeme` заменяется при запуске.
- Серверные сессии привязаны к ID пользователя; смена пароля и блокировка отзывают старые сессии, logout отзывает текущую.
- После смены собственного пароля интерфейс возвращает на страницу входа; для HTTPS доступен `XTTP_COOKIE_SECURE=1`.

### Bug Fixes
- Правила устройства больше не коммитятся в checkout и не перезаписываются при обновлении кода; удалены `XTTP_GIT_COMMIT` и `XTTP_SYNC_GROUPS`.
- Git-обновления используют только fast-forward и останавливаются при ошибке или расхождении истории вместо `reset --hard`.
- Чистая установка генерирует YAML-провайдеры до первого запуска mihomo; добавлен CLI `--prepare-config`.
- Обновления mihomo/Xray выбирают родные amd64/arm64 архивы; несовместимая архитектура отклоняется до остановки сервисов.
- Fleet устанавливает точные версии из манифеста, не подменяя их GitHub `latest`.
- Добавлены изолированные регрессионные проверки HTTP-сессий, генерации правил, обновления архивов, отката и сохранения Git-истории.
- Повреждённое хранилище сессий уходит в карантин без блокировки входа; чтение медленного HTTP-тела не удерживает блокировку пользователей.
- Общая обработка 401 охватывает все GET/POST/DELETE запросы интерфейса, включая статистику, соединения и логи.
- Прерванная чистая установка возобновляет подготовку через контрольный hash-маркер и не затирает отредактированный конфиг.
- Fleet unit берёт путь к скрипту из `XTTP_GIT_REPO`; описан безопасный переход со старого updater через отдельный checkout.
- При входе в панель выполняется read-only проверка опубликованного релиза; предложение открывается только для новой версии, установка требует отдельного подтверждения.
- Исправлены инвертированные цвета/ARIA-статусы сообщений обновления: успешный запуск фоновой проверки больше не выглядит ошибкой.
- Кнопка флота называется «Проверить и обновить», а сообщение о запуске не выдаёт его за завершённую установку.
- Диалог обновления соблюдает `hidden`: подтверждение не видно до нажатия «Обновить».
